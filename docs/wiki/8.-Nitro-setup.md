# Nitro, Flash and AIR clients

Atom can open three clients: Nitro, Flash and AIR.

## Nitro

1. Put the Nitro files in `public/`, or on an HTTPS host you trust.
2. In Housekeeping, under CMS settings, set **`nitro_path`** to the folder that holds Nitro's `index.html`. Do not add the file name.
3. Set `CLIENT_NITRO_ENABLED=true` in `.env`. This turns on badge external-texts support.

Atom opens the client at `<nitro_path>/index.html?sso=...`. The address holds a login ticket. Use only a host you control.

Check these things:

- `renderer-config.json` and `ui-config.json` must load from the folder you chose. A path that starts with `/` points to the host root. A relative path stays inside the client folder.
- Set the client and emulator addresses for your own server.
- Use HTTPS addresses for assets and sockets when your hotel uses HTTPS.

The setting `nitro_path` is the one the built-in theme uses. The old name `nitro_client_path` no longer works.

## Flash

1. Set `FLASH_CLIENT_ENABLED=true` to show the Flash option in the menu.
2. Set the variables for your client in `.env`. They are `EMULATOR_*`, `SWF_BASE_PATH`, `HABBO_SWF`, `PRODUCTION_FOLDER` and `EXTERNAL_*`. `.env.example` explains each one.

For badge management to edit the Flash external texts:

1. Set `CLIENT_FLASH_ENABLED=true`.
2. Set `CLIENT_FLASH_FILES_PATH` to the client folder, relative to `public/`.
3. Give write access to the external-texts files only.

## AIR

Use AIR when players start the official AIR client from a launcher that points to your domain.

1. Set `AIR_CLIENT_ENABLED=true` in `.env`.
2. Atom then answers `POST /api/v1/client/launch` with `client: "air"`. The answer is `habbo://hab?server=<APP_URL host>&token=<sso>`. The launcher uses it for the next start.

When the setting is off, the launch request returns 404. `GET /api/v1/bootstrap` reports the setting as `clients.air_enabled`.

Old client guides are listed in [troubleshooting](1.-Installing-Atom-CMS.md#troubleshooting). Their CMS steps are out of date.
