# VPN and IP restrictions

Atom can block VPNs and chosen IP addresses on the client routes. It is not a guarantee. A failed lookup lets the visitor in.

## Turn it on

In Housekeeping, under CMS settings:

1. Set `vpn_block_enabled=1`.
2. Set `ipdata_api_key` to a key from your [ipdata account](https://dashboard.ipdata.co/).

## Allow and block lists

Use these tables for your own lists:

- `website_ip_whitelist` for addresses to allow
- `website_ip_blacklist` for addresses to block

Each row has an `ip_address`, or an `asn` with the `whitelist_asn` or `blacklist_asn` flag.

Staff can skip the checks. The `bypass_vpn` permission in `website_permissions` sets the lowest staff rank that skips them.

## Order of checks

1. IP allow list, or staff bypass
2. IP block list
3. ASN allow and block lists, and the IP reputation check

An ASN allow entry does not override an IP block entry. A failed reputation lookup allows the request. Atom caches it for a short time.

## Good to know

- Set up [trusted proxies](1.-Installing-Atom-CMS.md#production-configuration), so Atom sees the visitor's real address.
- Developers can add the `vpn.checker` middleware to more routes in `routes/web.php`.
