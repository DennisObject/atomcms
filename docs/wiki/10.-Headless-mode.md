# Headless mode

Headless mode runs Atom CMS without a public website. Atom becomes an API and an admin panel. You build the website yourself, with any tool you like.

## Full mode and headless mode

| | Full mode (default) | Headless mode |
| --- | --- | --- |
| Public website | Atom shows it, with the Atom or Dusk theme | You build it (React, Vue, Next.js, or other) |
| API at `/api/v1` | Yes | Yes |
| Housekeeping at `/housekeeping` | Yes | Yes |
| Login and register pages | Atom shows them | Your frontend shows them. Atom answers with JSON. |
| Themes | Yes | No |
| Setup wizard at `/installation` | Yes | No. Use the command line. |

Switching mode never changes your hotel data. You can switch back at any time.

## Use headless mode when

- You want your own design or a different web framework.
- You want one site for the website and the game client.
- You run the frontend on another server or host.

If you only want the Atom or Dusk look, stay in full mode.

## What changes in headless mode

- Atom does not load the public web pages or the theme.
- Fortify, the login system, does not show pages. It answers with JSON.
- Atom sends people to your frontend for these pages: login, the user page, banned, maintenance, two-factor settings, forgot password, reset password and the shop. Reset password emails link to your frontend.
- After a PayPal payment, the buyer returns to your frontend shop page. The address has `order` and `payment_status` added.
- Until the hotel is installed, every `/api/v1` request returns status 503 with the code `installation_incomplete`.

## Before you start

Pick how your frontend and Atom share a login. Atom uses a cookie session. It has no bearer tokens.

| Your setup | Example | What you need |
| --- | --- | --- |
| Same host | Frontend and Atom on `hotel.example` | Nothing extra |
| Sibling hosts | `web.example.com` and `api.example.com` | A shared cookie domain: `--session-domain=example.com` |
| Unrelated domains | `site-a.com` and `api-b.com` | A same-origin proxy. Your frontend server forwards the API paths to Atom. |

Rules:

- Both addresses must use the same scheme, `http` or `https`.
- In production, both must use HTTPS.
- The frontend URL is an origin only: no path, no query, no user name or password. Example: `https://web.example.com`.
- The cookie domain must contain both hosts.

## Install a new hotel in headless mode

```bash
git clone https://github.com/DennisObject/atomcms.git
cd atomcms
composer install
npm ci
php artisan atom:install --headless \
  --frontend-url=https://web.example.com \
  --session-domain=example.com \
  --admin=YourAdminName
```

Leave out `--session-domain` when the frontend and Atom use the same host.

Options that are only for headless mode:

| Option | What it does |
| --- | --- |
| `--headless` | Installs without a theme. You cannot use it with `--theme`. |
| `--frontend-url=` | The origin of your frontend. |
| `--session-domain=` | The shared cookie domain for sibling hosts. |
| `--settings=` | A JSON file with the main hotel settings, for example `{"hotel_name": "My Hotel"}`. |
| `--admin=` | The user name of the first administrator. |

The installer completes the setup for you. You do not use the `/installation` page.

- If the user name does not exist, the installer creates it. It asks for the email and password. Without a terminal, set `ATOM_ADMIN_EMAIL` and `ATOM_ADMIN_PASSWORD` in the environment.
- If the user name exists, the installer makes that user the highest rank.
- An empty hotel always needs `--admin`.

All other installer options work too. See [installer options](1.-Installing-Atom-CMS.md#installer-options).

When the installer ends:

1. Restart your queue workers.
2. If you skipped the build, run `npm run build:housekeeping`. Housekeeping needs it.

## Switch an existing hotel

Finish the installation first. The switch needs a complete installation.

To go headless:

```bash
php artisan atom:mode headless --frontend-url=https://web.example.com --session-domain=example.com
```

To go back to the website:

```bash
php artisan atom:mode full
npm run build:atom
```

Build `build:dusk` instead if you use the Dusk theme. Full mode needs the public theme files.

What `atom:mode` does:

1. Checks your addresses.
2. Writes the settings below to `.env`.
3. Runs `config:cache` and `route:cache`. If one fails, it puts the old `.env` back.

Then restart queue workers and long-running servers.

If your host sets environment variables outside `.env`, add `--environment-managed`. Atom then prints the values and you set them yourself. Rebuild the config and route caches afterwards.

Check the current mode at any time:

```bash
php artisan atom:mode --status
```

## Settings written by `atom:mode`

| Setting | Meaning |
| --- | --- |
| `ATOM_MODE` | `full` or `headless` |
| `ATOM_FRONTEND_URL` | Origin of your frontend |
| `ATOM_CORS_ORIGINS` | Origins allowed to call Atom from a browser, with cookies. Separate several with commas. |
| `SANCTUM_STATEFUL_DOMAINS` | Hosts whose requests use the cookie session. Set to your frontend and backend hosts. |
| `SESSION_DOMAIN` | The shared cookie domain. Empty for the same host. |
| `SESSION_SECURE_COOKIE` | `true` when you use HTTPS |

The default `.env.example` lists local development hosts in `SANCTUM_STATEFUL_DOMAINS`: `localhost`, `127.0.0.1` and the two on port `5173`.

## Call the API from your frontend

Rules for every request:

- Send `Accept: application/json`.
- Send cookies (`credentials: 'include'` in `fetch`).
- For `POST`, `PUT` and `DELETE`, send the `X-XSRF-TOKEN` header. Its value is the `XSRF-TOKEN` cookie.
- Atom limits requests to 60 per minute for each user or IP address. Some actions have lower limits. For example, a voucher can be redeemed 5 times per minute.
- Money amounts are whole numbers in the smallest currency unit.

Sign in:

```js
const base = 'https://api.example.com';

// 1. Get the CSRF cookie.
await fetch(`${base}/sanctum/csrf-cookie`, { credentials: 'include' });

// 2. Log in.
const xsrf = decodeURIComponent(
  document.cookie.split('; ').find((c) => c.startsWith('XSRF-TOKEN=')).split('=')[1],
);
await fetch(`${base}/login`, {
  method: 'POST',
  credentials: 'include',
  headers: { 'Accept': 'application/json', 'Content-Type': 'application/json', 'X-XSRF-TOKEN': xsrf },
  body: JSON.stringify({ username: 'name', password: 'secret' }),
});

// 3. Read the user.
const me = await fetch(`${base}/api/v1/me`, { credentials: 'include', headers: { Accept: 'application/json' } });
```

If the user has two-factor authentication, send the code to `POST /two-factor-challenge`.

## Main endpoints

Call these two first:

| Endpoint | Returns |
| --- | --- |
| `GET /api/v1/status` | Is the hotel installed, is maintenance on, the mode, and the maintenance message and tasks |
| `GET /api/v1/bootstrap` | Hotel name, color mode, logo paths, bot protection keys, supported clients, registration rules, currency, and what the current user may do |

Other areas:

| Area | Paths |
| --- | --- |
| News | `/api/v1/articles`, comments and reactions |
| Users | `/api/v1/users`, `/api/v1/users/online`, `/api/v1/me`, `/api/v1/me/account`, `/api/v1/me/password`, `/api/v1/me/sessions` |
| Shop | `/api/v1/shop`, purchases, vouchers, PayPal orders |
| Homes | `/api/v1/homes/{user}`, the home shop and inventory |
| Community | `/api/v1/staff`, `/api/v1/teams`, `/api/v1/leaderboards`, `/api/v1/photos`, `/api/v1/applications`, `/api/v1/rules` |
| Support | `/api/v1/support/tickets` |
| Other | `/api/v1/badges`, `/api/v1/rare-values`, `/api/v1/client/launch` |
| Login | `/sanctum/csrf-cookie`, `/login`, `/logout`, `/register`, `/forgot-password`, `/reset-password/{token}` |

The complete contract is in `docs/api/openapi.json`. TypeScript types are in `docs/api/schema.d.ts`.

Many endpoints need a signed-in user. Others are public.

## CORS

CORS decides which websites may call Atom from a browser.

- Add your frontend origin to `ATOM_CORS_ORIGINS`. Atom then allows cookies for that origin.
- Other origins get no cookies.
- Some older public endpoints, like `/api/online-count`, allow every origin without cookies.

## Change the frontend pages

Atom builds links to your frontend from `config/atom.php`, under `frontend_paths`:

| Page | Default path |
| --- | --- |
| Welcome | `/` |
| Login | `/login` |
| User page | `/me` |
| Banned | `/banned` |
| Maintenance | `/maintenance` |
| Two-factor settings | `/settings/two-factor` |
| Forgot password | `/forgot-password` |
| Reset password | `/reset-password/{token}` |
| Shop and PayPal return | `/shop` |

Change a path there, then rebuild the config cache. A path must start with `/`.

## Housekeeping

Housekeeping works as in full mode, at `/housekeeping` on the Atom host. It needs its own assets. Build them with:

```bash
npm run build:housekeeping
```

## Troubleshooting

| Problem | Likely cause and fix |
| --- | --- |
| Status 503, code `installation_incomplete` | The hotel is not installed. Run `php artisan atom:setup --complete`. |
| Status 419 (CSRF token mismatch) | Get `/sanctum/csrf-cookie` first. Send `X-XSRF-TOKEN`. Send cookies. Check `SANCTUM_STATEFUL_DOMAINS` and `SESSION_DOMAIN`. |
| The browser blocks the request (CORS) | Your frontend origin must match `ATOM_CORS_ORIGINS` exactly: scheme, host and port. |
| You log in, but the next request says you are signed out | The cookie is not shared. Check `SESSION_DOMAIN`, `SESSION_SECURE_COOKIE` and HTTPS. For unrelated domains, use a same-origin proxy. |
| Housekeeping has no styles | Run `npm run build:housekeeping`. |
| A setting change does nothing | Run `php artisan config:cache` and restart workers. |
| `atom:mode` says a value is externally managed | Use `--environment-managed` and set the value in your deployment. |
