# Install and update Atom CMS

This guide shows how to install Atom CMS, keep it up to date and fix common problems.

To run Atom without a website, see [headless mode](10.-Headless-mode.md).

## Requirements

- PHP 8.5 or newer
- Composer 2
- Node.js (LTS, compatible with `package.json`)
- MySQL or MariaDB that works with your emulator. CI uses MariaDB 11.8.
- An emulator: Arcturus Morningstar 3.5.5 or Ada. A hotel uses one emulator for its whole life.

Atom needs these PHP extensions. If one is missing, remove the semicolon (`;`) in front of it in `php.ini`:

```ini
extension=curl
extension=fileinfo
extension=gd
extension=mbstring
extension=openssl
extension=pdo_mysql
extension=sockets
extension=intl
```

Laravel also needs Ctype, DOM, Filter, Hash, PCRE, PDO, Session, Tokenizer and XML. After you install the dependencies, run `composer check-platform-reqs` to check. See [Laravel's server requirements](https://laravel.com/docs/13.x/deployment#server-requirements).

## First installation

Keep the site private until the browser installation is done. Run the commands from the repository root, as the deployment user.

```bash
git clone https://github.com/DennisObject/atomcms.git
cd atomcms
composer setup
```

`composer setup` does everything for you:

1. Copies `.env.example` to `.env` when needed.
2. Installs the PHP and Node dependencies.
3. Runs the installer (`atom:install`). It asks for your emulator, sets up the database, creates the app key, links storage, runs migrations and seeders, and builds your theme.

Then:

1. Set `APP_URL` in `.env` to your site address. The defaults for database and mail point to local Docker services. Change them if you do not use Docker Compose.
2. Point your web server to the `public/` folder.
3. Open `/installation` in your browser and enter your hotel details.

For local tests, run `php artisan serve --host=127.0.0.1`. Do not use it for a live hotel.

### Ada

Start Ada first, so it creates its own database tables. Then choose Ada in the installer.

### An existing hotel

Back up the database first. The installer never replaces a database that already has an emulator in it, even with `--fresh`.

To add Atom to such a database, run the installer with `--skip-arcturus` (or the matching `--emulator`). It then adds only Atom's own tables.

Atom keeps password reset tokens in `website_password_resets`. The emulator owns `password_resets`, so Atom does not touch it.

### Install step by step

Use this to install the dependencies yourself. Use it only for a new checkout. When you update, keep your existing `.env` and `APP_KEY`.

```bash
cp .env.example .env
# Edit .env: set the database and APP_URL.
composer install
npm ci
php artisan atom:install --emulator=arcturus
```

On Windows, use `copy .env.example .env` (Command Prompt) or `Copy-Item .env.example .env` (PowerShell). For Ada, use `--emulator=ada`.

### Installer options

| Option | What it does |
| --- | --- |
| `--emulator=ada` | Installs Atom for Ada's existing database. |
| `--skip-arcturus` | Keeps an existing Arcturus database. Skips the base and catalog imports. |
| `--sql=/path/to/database.sql` | Uses your own Arcturus dump (`.sql` or `.sql.gz`). |
| `--catalog-sql=/path/to/catalog.sql` | Imports your own catalog after the base. |
| `--skip-catalog` | Keeps the catalog from the base dump. |
| `--theme=atom` or `--theme=dusk` | Activates and builds that theme. |
| `--skip-build` | Skips the build. Run `npm run build:atom` or `npm run build:dusk` yourself. |
| `--fresh` | Deletes tables. Use it only on a throwaway database. Refused for a hotel database. |
| `--headless` | Installs without a website. See [headless mode](10.-Headless-mode.md). |

### Docker Compose

Compose has two databases with separate storage: `mariadb` and `mariadb-ada`.

- Ada uses `mariadb-ada:3306` inside Compose, or `127.0.0.1:3308` from your computer.
- The default database is `atomcms_ada`, with user `atomcms` and password `password`. Change these on a live server.
- Point Ada at this database first. Then point Atom's `DB_*` settings at it and set `EMULATOR_DRIVER=ada`.

## Web server permissions

- The web server must serve only the `public/` folder.
- The web process needs read access to the app files.
- The web process needs write access to `storage/` and `bootstrap/cache/`.
- Keep the source code, `.env`, dependency files and Git files owned by the deployment user.

On Linux, replace `www-data` with the group of your web process:

```bash
sudo chown -R "$USER":www-data storage bootstrap/cache
chmod -R u+rwX,g+rwX,o-rwx storage bootstrap/cache
```

On IIS, give the site's app pool identity (for example `IIS AppPool\AtomCMS`) read and execute access to the app, and **Modify** access to `storage` and `bootstrap/cache`. Do not give `IUSR` or `IIS_IUSRS` full control. Creating the `public/storage` link can need Windows Developer Mode or an elevated command. The web process itself does not need to be elevated.

Badge management can write the Nitro and Flash external-texts files. If you use it, give write access to those files and their folders only. Do not make the whole client writable.

## Production configuration

Set these before you cache the configuration:

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=https://hotel.example
SESSION_SECURE_COOKIE=true
TRUSTED_PROXIES=
```

- **`TRUSTED_PROXIES`:** leave it empty when visitors reach the server directly. Behind a reverse proxy, list the exact proxy IPs or ranges, separated by commas. Use `*` only when the server accepts traffic from your proxies alone, and they replace forwarded headers sent by visitors. Atom uses visitor IPs for bans, rate limits and registration limits.
- **HTTPS:** set it up on the web server or proxy. `FORCE_HTTPS=true` only makes Laravel create HTTPS links. It does not set up TLS.
- **Secrets:** keep `.env` and backups outside the public folder. Keep the same `APP_KEY` on every deployment, or encrypted data becomes unreadable.
- **Mail:** set real SMTP details and a valid sender. Password reset mail needs them.
- **Bots:** set up [bot protection](4.-Bot-protection.md) before you open registration.
- **Cloudflare:** turn off Rocket Loader. It breaks Atom's JavaScript.

## Updating an installed hotel

1. Back up the database, `.env` and uploaded files. Test the release on a copy of your database first.
2. Run:

   ```bash
   php artisan down
   # Deploy the new code here. Keep .env and storage/.
   composer install --no-dev --prefer-dist --optimize-autoloader
   composer check-platform-reqs --no-dev
   npm ci
   npm run build:atom
   npm run build:dusk
   php artisan config:clear
   php artisan migrate --force
   php artisan storage:link
   php artisan optimize
   php artisan reload
   php artisan up
   ```

3. Run `php artisan up` only when every step before it worked.
4. Restart PHP and opcache if your host needs it. Use a process monitor to restart long-running processes after `reload`.

Good to know:

- Build both themes if both must stay available. If you ship one theme, build only that one. You can also build in CI instead of on the server.
- Use `migrate` to update. Never use `migrate:fresh`, base SQL imports or `composer setup` for an update.
- Run extra seeders only when the release notes say so. Seeders can change existing content.
- Do not turn on `RENAME_COLLIDING_TABLES` as a general setting. Check each collision and back up the data first.
- `optimize` caches config, events, routes and views. After you change `.env`, run `php artisan config:cache`. See [configuration caching](https://laravel.com/docs/13.x/configuration#configuration-caching).

## Migrating from another CMS

Back up the database and check each table collision before you migrate. With `RENAME_COLLIDING_TABLES=true`, migrations rename colliding tables and columns to `old_<timestamp>_<name>`. This does not merge data. Leave it off unless the old data is safe to archive.

## Scheduler and queues

Atom checks pending PayPal orders every five minutes (`paypal:reconcile`). For this, run Laravel's scheduler every minute. This applies even when the queue stays on `sync`.

On Linux, add this cron job:

```cron
* * * * * cd /path/to/atomcms && php artisan schedule:run >> /dev/null 2>&1
```

On Windows, use Task Scheduler. Run `php artisan schedule:run` every minute, with the repository as the working folder. Run `php artisan schedule:list` to check that the task exists. See [Laravel scheduling](https://laravel.com/docs/13.x/scheduling#running-the-scheduler).

The default queue is `QUEUE_CONNECTION=sync`, which runs jobs at once. If you switch to an asynchronous queue, set up its storage and run supervised workers. See [Laravel queues](https://laravel.com/docs/13.x/queues#running-the-queue-worker).

## Troubleshooting

**cURL error 60 on Windows.** PHP cannot check certificates.

1. Download the [CA bundle](https://curl.se/docs/caextract.html) and save it as `C:/certs/cacert.pem`.
2. Add this to the `php.ini` of the failing process:

   ```ini
   curl.cainfo = "C:/certs/cacert.pem"
   openssl.cafile = "C:/certs/cacert.pem"
   ```

3. Restart PHP or the web server. Keep certificate checks on.

**Something fails and you do not see why.** Read [error logging](Error-logging.md).
